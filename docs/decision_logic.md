# 경영 의사결정 계산 명세 — E01

- 작성일: 2026-10-20 (E01 명세 단계, 검토 대기)
- 데이터 정의: [manufacturing_data_schema.md](manufacturing_data_schema.md) / 관련 질문: [ontology_competency_questions.md](ontology_competency_questions.md)

> **이 문서의 계산식은 모두 PoC 검증용으로 단순화한 가정이다.** 실제 기업의 MRP·APS 로직(로트 크기, 다중 사업장, 유한 능력 일정계획 등)을 대표하지 않는다. 납기 판정 기준, 원가 구성, 안전재고 반영 방식 등 기업마다 다른 기준은 **확정하지 않고 파라미터로 남긴다.**
>
> 수치 계산은 규칙 계산(또는 최적화 도구)이 수행한다. LLM은 계산 결과의 설명만 맡고 수치를 만들지 않는다(업무분장 원칙).

## 0. 공통 정의

| 기호 | 의미 | 출처 필드 |
|---|---|---|
| H | 계획 기간 [horizon_start, horizon_end] | ProductionPlan |
| D(p) | 기간 H 안에 납기가 있는 OPEN 주문의 제품 p 수량 합 | Order.order_qty (단위 환산 후) |
| OH(i) | 품목 i의 기준일 보유 재고 | Inventory.on_hand_qty |
| AL(i) | 품목 i의 할당 수량 | Inventory.allocated_qty (없으면 0) |
| SO(i) | 품목 i의 기간 내 입고 예정 수량 | Inventory.on_order_qty (expected_receipt_date ∈ H) |
| SS(i) | 안전재고 | Product/Material.safety_stock_qty (없으면 0) |
| q(b, c) | BOM b에서 구성품 c의 base_qty당 소요량 | BOMLine.qty_per / BOM.base_qty |
| s(b, c) | 손실률 | BOMLine.scrap_rate (없으면 0) |
| conv(u→v) | 단위 환산 | Unit.to_base_factor |

- **모든 수량은 계산 전에 품목의 기준 단위로 환산한다.** 환산 불가(차원 불일치)면 계산을 중단하고 ERR-UNIT으로 보고한다.
- **적용 BOM**: (제품, 기준일, 생산수량, 사이트) 조건으로 [schema §3.6의 BOM 버전 선택 규칙](manufacturing_data_schema.md)을 적용해 정확히 1개가 선택될 때만 계산한다. 0개(선택 불가) 또는 2개 이상(모호)이면 ERR-BOMVER로 보고하고 해당 제품 계산을 중단한다. 생산수량은 1절의 생산필요량을 쓴다.
- **초기 범위 가정** ([schema §1.1](manufacturing_data_schema.md)): 계획 단위는 주간(4주), 근무는 주 5일, 화폐는 KRW, 단위는 EA·kg·g·h. 주간 가용시간 = regular_hours_per_day × 5.
- 검증 오류가 있는 레코드는 계산에 쓰지 않으며, 결과에 "제외된 레코드 수"를 함께 낸다.

## 1. 생산 필요량

**목적**: 제품별로 기간 내 얼마를 생산해야 하는가.

```
가용재고(p)   = OH(p) − AL(p) + SO(p)
생산필요량(p) = max(0, D(p) + SS(p) − 가용재고(p))
```

- 예시(업무분장): 수요 1,000, 완제품 재고 200, 안전재고 100 → 1,000 + 100 − 200 = **900**.
- 수요를 확정 주문만으로 할지, 예측 수요(예측·최적화 담당의 모델 결과)를 더할지는 **미확정**. 파라미터 `demand_source ∈ {ORDERS, FORECAST, MAX(ORDERS, FORECAST)}`로 둔다.
- 안전재고를 필요량에 포함할지 여부도 기업 기준이므로 파라미터 `include_safety_stock`(기본 TRUE, 팀 합의 필요).
- 로트 크기·최소 생산량은 반영하지 않는다(가정).

## 2. 자재 총소요량 (BOM 전개)

**목적**: 생산 필요량을 만들기 위해 자재가 얼마나 필요한가.

```
총소요량(c) = Σ_p 생산필요량(p) × q(b_p, c) × (1 + s(b_p, c))       (단일 수준)
```

- 다단계: 구성품이 반제품(`component_type = PRODUCT`)이면 그 반제품의 생산필요량을 위 1절과 같은 방식(반제품 재고 차감)으로 구하고 재귀적으로 전개한다. 전개 순서는 상위→하위(low-level code 순). 순환(ERR-BOMCYCLE)이 있으면 전개를 중단한다.
- 반제품 재고를 전개 시 차감할지(순소요 전개) 여부는 파라미터 `net_semi_finished`(기본 TRUE).
- 예시(업무분장): 생산필요량 900개 × 2 kg/개 = **1,800 kg** (손실률 0 가정).

### 2.1 다단계 BOM 전개 순서 (중복 차감·중복 전개 방지)

반제품(SF)은 여러 완제품(FG)의 구성품이 될 수 있다. 부모별로 따로 재고를 차감하거나 부모별로 따로 전개하면 **반제품 재고가 여러 번 차감**되거나 **같은 수요가 두 번 전개**된다. 다음 순서를 지킨다.

1. **저수준 코드(LLC) 계산**: 각 품목이 BOM 트리에서 나타나는 가장 깊은 수준을 LLC로 정한다 (FG = 0, FG 바로 아래 SF = 1, …). 같은 SF가 여러 수준에 나오면 가장 깊은 수준을 쓴다.
2. **LLC 오름차순으로 처리**: LLC = k인 품목은 LLC < k인 모든 부모의 순소요가 확정된 뒤에만 처리한다.
3. **수요 집계 → 1회 차감**: 품목 i의 총수요 = 독립수요(주문) + Σ_부모 [부모 순소요 × 부모 BOM의 i 소요량 × (1 + 손실률)]. 이 **합계에서 재고를 한 번만** 차감해 순소요를 구한다: 순소요(i) = max(0, 총수요(i) + SS(i) − 가용(i)).
4. **순소요만 전개**: 품목 i의 하위 구성품 수요는 i의 **순소요**(총수요가 아님)에 i의 BOM을 곱해 만든다. 각 품목은 한 번만 전개한다.
5. **자재 집계**: 자재는 모든 부모(FG·SF)의 순소요 × 소요량을 기준 단위로 환산해 합산한 뒤, 자재 재고를 한 번만 차감한다(3절).
6. **BOM 선택**: 각 품목의 BOM 버전은 그 품목의 순소요 수량과 기준일로 한 번만 선택한다(§0 적용 BOM).

**예시 (설명용 수치, 실제 데이터 아님)**

| 품목 | 값 |
|---|---|
| FG-A 순소요 | 100 EA, BOM: SF-X 1 EA/개 |
| FG-B 순소요 | 50 EA, BOM: SF-X 2 EA/개 |
| SF-X 가용재고 / 안전재고 | 80 EA / 0 |
| SF-X BOM | 자재 M-c 300 g/개 (자재 기준 단위 kg) |

- 올바른 계산: SF-X 총수요 = 100×1 + 50×2 = **200**, 순소요 = max(0, 200 − 80) = **120**, M-c 소요 = 120 × 300 g = 36,000 g = **36 kg**.
- 잘못된 계산 ① 부모별 차감: (100 − 80) + (100 − 80) = 40 → 재고 80을 두 번 차감해 **80 EA 과소** 계산.
- 잘못된 계산 ② 총수요로 전개: 200 × 0.3 kg = 60 kg → 재고로 충당되는 80 EA까지 자재를 전개해 **24 kg 과대** 계산.

## 3. 재고 부족량

**목적**: 어떤 자재가 얼마나 부족한가.

```
자재가용(m) = OH(m) − AL(m) + SO(m)
부족량(m)   = max(0, 총소요량(m) + SS(m)·α − 자재가용(m))      α = include_material_safety_stock ? 1 : 0
```

- 예시(업무분장): 총소요량 1,800 kg, 보유 1,500 kg, 할당·입고예정·안전재고 0 → **300 kg 부족**.
- 업무분장에 따르면 외주 생산 시 자재를 누가 부담하는지에 따라 필요량이 달라진다. 외주 라인은 파라미터 `outsourcer_supplies_material`(기본 미정)로 처리하며, TRUE이면 해당 수량을 자재 소요에서 뺀다.
- 입고 예정일이 필요 시점보다 늦은 SO는 가용에서 뺄지 여부 → 4절 납기 판정에서 반영한다(이 절에서는 기간 합계만).

## 4. 납기 가능 여부

**목적**: 주문별로 납기 안에 공급할 수 있는가, 아니라면 왜인가.

판정은 아래 세 조건으로 나누고, 각 조건의 위반 사유를 따로 출력한다.

| 조건 | 계산 (단순화) | 위반 사유 코드 |
|---|---|---|
| ① 자재 준비 | 부족 자재가 있으면 자재준비일 = 기준일 + max(해당 자재 우선 공급사 lead_time_days). 부족이 없으면 기준일 | `MATERIAL_LEADTIME` |
| ② 생산능력 | 필요시간(r) = Σ 생산필요량(p) × run_time_per_unit_h + setup_time_h. 가용시간(r) = regular_hours_per_day × 근무일수(기준일~납기, 주 5일) [+ 잔업 허용 시 overtime 최대]. 주간 계획에서는 주별로 계산해 누적. 필요 > 가용이면 위반 | `CAPACITY_EXCEEDED` |
| ③ 완료일 | 예상완료일 = 자재준비일 + max(manuf_lead_time_days, ⌈필요시간/일 가용시간⌉) . 예상완료일 > due_date이면 위반 | `DUE_DATE_MISSED` |
| 데이터 | 필수 입력(BOM, 공정, 재고, 리드타임) 누락·오류 | `DATA_INVALID` |

- 출력 형태: 주문별 `{order_id, feasible: true/false/unknown, reasons: [...], expected_completion_date, slack_days}`. 데이터 오류로 판정할 수 없으면 `unknown`이며 `false`로 처리하지 않는다.
- 단순화 가정: 주문 간 자원 경합은 납기 순(EDD)으로 앞 주문부터 자원 시간을 차감해 처리한다. 공정 간 대기·이동 시간, 교대 근무, 공휴일, 부분 납품은 반영하지 않는다.
- **납기 판정 기준(며칠 여유를 허용할지, 부분 납품 인정 여부 등)은 기업마다 다르므로 확정하지 않는다.**

## 5. 생산계획별 비용 및 제약 비교

**목적**: 복수 계획안(예: 정규생산안, 잔업안, 외주안 — 이름은 예시)을 같은 기준으로 비교한다.

**비용 구성 (각 항목 개별 출력, 합계는 참고값)**

| 항목 | 계산 | 필요한 값 | 상태 |
|---|---|---|---|
| 자재비 | Σ 자재 사용량 × Material.unit_cost | 자재 단가 | 합성, KRW (초기 제안값) |
| 정규 생산비 | Σ REGULAR 라인 필요시간 × cost_per_hour | 시간당 비용 | 합성 |
| 잔업비 | Σ OVERTIME 라인 필요시간 × overtime_cost_per_hour | 잔업 단가 | 합성, 기업별 미확정 |
| 외주비 | Σ OUTSOURCE 수량 × outsourcing_unit_cost | 외주 단가 | 합성, 기업별 미확정 |
| 재고 유지비 | 기간말 재고 × 유지비율 | 유지비율 | **미확정** (팀 합의 전까지 계산하지 않고 `미산정` 표기) |
| 납기 지연 비용 | 지연 주문·지연일 × 페널티 | 페널티 기준 | **미확정** (금액 대신 지연 건수·일수만 출력) |

**제약 위반 지표 (금액으로 바꾸지 않고 그대로 출력)**

| 지표 | 계산 |
|---|---|
| 능력 초과 시간 | Σ_r max(0, 필요시간(r) − 가용시간(r)) |
| 자재 부족 수량 | Σ_m 부족량(m) (자재별 목록 포함) |
| 납기 지연 주문 수 / 총 지연일 | 4절 결과 집계 |
| 데이터 오류로 판정 불가 주문 수 | 4절 `unknown` 집계 |

- 비용과 제약 위반을 하나의 점수로 합치는 **가중치는 정하지 않는다**(현장 KPI 우선순위는 산업데이터·KPI 조사 담당의 조사 및 수요기업 확인 후 결정). 비교 결과는 표로 나란히 제시하고, 선택은 사용자가 한다.
- 최적화(OR-Tools 등)로 계획안을 만드는 방법은 예측·최적화 담당의 실험 범위이며, 이 문서는 **평가 기준**만 정의한다.

## 6. 계산 결과의 검증 방법 (E01 정답셋 연계)

- 정답 원천(canonical JSON)에서 위 계산을 **독립 구현**(별도 스크립트, 또는 스프레드시트 수계산)으로 미리 계산해 기대값으로 고정한다.
- 검증 케이스는 업무분장의 필수 케이스를 따른다: 정상 / 누락·중복·단위 불일치 / 수요 급증 / 자재 부족 / 생산능력 초과. (API 장애 케이스는 이 계산과 무관)
- 각 케이스의 기대 결과에는 수치와 함께 **위반 사유 코드**를 포함한다.

### 6.1 E01 구현 규칙 (2026-10-20, 정답셋 생성·검증에 적용)

위 1~5절에서 열어 둔 부분을 E01 정답셋에서는 아래처럼 고정했다. 구현 A(`scripts/e01_expected.py`)와 구현 B(`scripts/e01_verify.py`)는 이 규칙을 각각 따로 구현해 결과를 대조한다. 모두 **PoC 가정**이다.

| 항목 | E01 규칙 |
|---|---|
| 수요 | 계획 기간(2026-11-16~12-13) 안에 납기가 있는 `OPEN` 주문만. `CLOSED`·`CANCELLED` 제외 |
| 가용재고 (1~3절) | 보유 − 할당 + 입고예정(예정일 ≤ 계획 종료일). 단위는 품목 기준 단위로 환산 |
| 계획 기간 BOM 선택 | 기준일 = 계획 시작일, 수량 = 그 품목의 순소요 |
| 안전재고 | 제품·자재 모두 포함 (`include_safety_stock`, `include_material_safety_stock` = TRUE) |
| 계획 기간 자원 부하 | 품목별 순소요 × 단위 가공시간 + 공정별 준비시간 1회. 정규 가용 = 일 정규시간 × 근무일 20일 |
| **4절 주문 판정** | ① 납기순(같으면 주문번호순)으로 처리 ② 완제품 재고(보유 − 할당, 입고예정 제외)를 먼저 배정하고 나머지를 생산 ③ 생산분은 계획 기간 적용 BOM으로 반제품 소요를 만들고 반제품 재고를 납기순으로 배정, 부족분은 반제품 생산 ④ 고려 자재 = 완제품 BOM 자재 + 생산하는 반제품의 BOM 자재. 그중 3절 부족량 > 0인 자재의 **우선 공급사 리드타임 최대값**만큼 기준일에서 달력일로 더한 날이 자재준비일 ⑤ 생산일수 N = max(완제품 생산 리드타임 + 생산하는 반제품 중 최대 생산 리드타임, ⌈자원별 주문 소요시간 ÷ 일 정규시간⌉의 최대값) ⑥ 예상완료일 = 자재준비일 다음 근무일부터 N 근무일째 (재고 출하만이면 기준일) ⑦ 능력: 자원별 누적 소요시간(납기순) > 일 정규시간 × (기준일 다음날~납기 근무일수)이면 `CAPACITY_EXCEEDED` (잔업 미반영) ⑧ `DUE_DATE_MISSED` = 예상완료일 > 납기 ⑨ `MATERIAL_LEADTIME` = 납기를 놓쳤고, 자재 대기가 없었다면(기준일 시작) 납기를 지켰을 경우 |
| **5절 계획안 평가 (v2, 정답셋 v2부터 적용)** | ① 세 안 모두 같은 주문·재고·자재·BOM·납기 조건과 같은 **완제품 주별 총수량**(자체 + 외주)을 쓴다 ② 자체 생산 라인마다 제품의 모든 공정에 (수량 × 단위 가공시간 + 준비시간)을 그 주·자원 필요시간에 더한다 ③ 자체 가용시간: 정규생산안·외주안 = 정규(일 정규시간 × 5), **잔업안 = 정규 + 잔업 최대(일 잔업최대 × 5)** ④ 실제 정규 근무 = min(필요, 정규), **실제 잔업 = min(max(0, 필요 − 정규), 잔업 가용)**, 능력 초과 = max(0, 필요 − 자체 가용) ⑤ 비용: 정규 생산비 = 실제 정규 근무 × 시간당 비용, 잔업비 = 실제 잔업 × 잔업 단가, 외주비 = **명시 외주 수량** × 외주 단가, 자재비 = 자체 생산 계획 수량의 자재 소요 × 단가(외주분 자재는 외주처 부담) ⑥ 완료 수량: 자원·주마다 비율 = min(1, 자체 가용 ÷ 필요), 라인 완료 수량 = ⌊계획 수량 × 공정 자원 비율의 최소값⌋ (정수 EA, 분수로 정확 계산). 자체 생산 완료일 = 그 주 금요일 ⑦ 외주 입고일 = 주 시작일 + 외주 리드타임 ⑧ 납기 지연: 제품별 납기순 누적 수요가 납기일까지의 누적 공급(재고 보유 − 할당 + 완료·입고 수량)보다 크면 지연, 부족 수량 기록 (반제품 능력 부족은 반제품 라인 미생산량으로만 보고하고 완제품 공급에는 반영하지 않음 — 단순화) ⑨ 재고 유지비·지연 페널티는 `미산정` |
| 생산계획안 (입력 데이터, v2) | 완제품: 주별 lot-for-lot (주초 예상재고가 안전재고 아래로 내려가는 만큼 그 주에 생산) — 세 안 동일. 외주안: FG003 주별 수량 중 가상 외주처 능력(150 EA/주)까지를 명시 외주 수량으로, 나머지를 자체 생산. 반제품 수요는 자체 생산 완제품에서만 발생. 잔업 허용은 계획 단위 속성(`overtime_allowed`)이며 라인에 잔업 표시를 하지 않는다 |
| 가상 외주처 (합성 가정) | OUTSOURCER-1: FG003만, 능력 150 EA/주, 리드타임 7일, 자재 외주처 부담 |
