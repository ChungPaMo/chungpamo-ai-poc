## 1. 결함 (기준선 v1)

같은 행에 제품코드(`0001002` → FG002)와 제품명(`가정용 히터 A` → FG001)이 서로 다른 마스터를 가리킬 때, v1 매퍼는 나중 후보(코드)로 **경고 없이 덮어썼고**, 실험용 자동 승인 정책이 "모든 후보가 규칙 기반 + 오류 0"만 보고 반영했다 → 잘못된 반영 1건(O032 = FG002). 승인자 정책과 무관하게 자동 승인 단계에서 발생.

## 4. 남은 한계

- 충돌을 막기만 하고 해결(승인자가 후보 중 하나를 지정)하는 기능은 없다 — 재반입으로 처리.
- 교차 필드 규칙은 제품코드·제품명 한 쌍만 실측. 자재·공급사 이름, 단위 문자열과 코드의 충돌은 미측정.
- "그럴듯하지만 틀린 단일 후보"(근거가 하나뿐인 오기)는 규칙으로 잡을 수 없다 — 자동 승인 기본값을 REVIEW_REQUIRED로 둔 이유.
- 평가셋·충돌 세트와 규칙을 같은 작성자가 만들었다. 실제 업체 문서 일반화 성능이 아니다.
