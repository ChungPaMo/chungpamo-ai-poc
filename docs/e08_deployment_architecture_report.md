## 2. 배치 방식 비교

| 지표 | 1. CPU 로컬 | 2. 외부 API | 3. 하이브리드 (로컬 기본 + 선택적 API) |
|---|---|---|---|
| 처리시간 | 정형·텍스트형 문서·검증·매핑 모두 1초 이내 (실측) | 문서 1건 8~10 s (실측 2회), 다른 기능은 API 대상 아님 | 로컬 경로는 1과 같음, API 문서만 추가 지연 |
| 메모리 | 수십~수백 MB (RDF 제외) | 로컬 부담 작음 (미측정) | 1과 같음 |
| 예상 API 비용 | 0 | Document Parse 쪽당 공개 단가 기준(실측 2회 추정 $0.02·$0.03), 실제 청구 미확인. LLM 비용 미측정 | API로 보내는 문서 비율에 비례 — 비율 미정 |
| GPU 필요 | 실측 범위 불필요 | 불필요 (공급사 측) | 불필요 |
| 오프라인·인터넷 불가 | **가능** (실측 기능 전부) | 불가 | 로컬 경로만 가능, API 문서는 대기·수동 처리 |
| 기업 보안·사내망 | 데이터 외부 반출 없음 | 문서 원본 외부 전송 — 반출 승인·보존·재학습 정책 확인 필요(미확정) | 전송 대상 문서 유형을 규칙으로 한정 + 전송 로그 |

| 운영 복잡도 | 낮음 (Python + SQLite) | 중간 (키 관리·요금·한도·네트워크) | 가장 높음 (라우팅 규칙·두 경로 결과 형식 통일·로그) |
| 품질 근거 | 텍스트형 PDF에서 API와 같은 셀 정확도(2건) | 병합 셀 1건 우세, 스캔은 미측정 | 스캔·복잡 표에서만 API 이점이 확인되면 의미 있음 |

## 3. 권고 (조건부)

- **기본안: CPU 로컬** — 실측한 모든 기능(정형 파싱, 텍스트형 문서 파싱, Python/SQLite 검증, 모의 ERP 매핑·승인)이 GPU 없이 1초 이내·수백 MB 이하로 동작했고, 사내망·오프라인 조건을 만족한다.
- **하이브리드는 조건부 후보** — 스캔 PDF·복잡 병합 표처럼 로컬 파서가 실패하는 문서 유형이 실측으로 확인되고, 외부 전송이 승인될 때만. API 결과도 E10 staging·승인을 거치게 하여 API 장애·오류가 ERP에 바로 들어가지 않게 한다.
- **전체 외부 API는 권고하지 않음** — 실측 범위에서 정확도 이익이 없고 비용·보안·장애 의존이 추가된다.
- RDF/SHACL은 어떤 배치에서도 운영 경로에 넣지 않는다 (L 규모 검증 70분·0.7 GB, E06).
